# 对象表面新观测：有限探针收尾与主线约束

主线是 **omni_slam 持续对象级语义建图**：LIVO 提供定位和实测几何，对象地图维护类别、三维范围、跨帧身份与观测来源。验收对象是完整地图，公开室外 benchmark 优先，随后验证同一模块在机器人数据上的表现。局部分割改善不能替代完整对象恢复和实例指标改善。

本记录整理已经执行的探针，没有追加推理、训练或建图。保留原强基线，新掩码未写回地图。

## 同输入探针及结果

在两个已参与开发的 KITTI-360 窗口，各固定四个建筑、四个车辆候选。候选和视图按旧对象实测来源及未归属表面选择，不用参考标签。相同三个物理像素正提示分别输入原图与局部裁剪；SAM3 保留全部原生输出，按原生质量分数选择掩码，不根据参考标签或提示满足程度重选。

共16个案例、32次图像编码和32次实例解码；全部预测封存后才读取参考标签。两个分支在16例中均产生不同的来源点选择。裁剪同时改变上下文及采样分辨率，不能将差异仅归因于分辨率，也不能把裁剪本身视为创新。

## 对主线的决定

封存此探针，不继续搜索裁剪比例、提示或解码变体。它未证明应替换现有前端，也未验证有效的地图修订机制。新机制必须回答：如何利用观测证据纠正历史对象归属或恢复遗漏表面，并在完整地图中保住原来正确的对象。

下一次实施前应明确一个待修正的地图错误、可用证据、更新算子及同输入简单对照。实施后的交付必须包含完整地图实例指标、逐对象新增与丢失匹配以及必要消融；通过开发验收才扩展到未参与开发的场景和同版本机器人验证。已经看过的窗口不再作为独立测试。当前有效新机制和独立泛化尚未完成。

关于用户追问“为什么结果一样”：[联合修订核查](joint_semantic_revision_2026-11-14.md)已确认 Ours 候选与 Class only 有55/100个地图点归属不同，但没有形成额外 AP 收益。该候选不能因内部产生变化就升级为正式 Ours。
