# VGGT 对 omni_slam 对象建图路线的启发

2026-11-13。用户提出借鉴多图 token 建模与交替帧内/跨帧注意力。本文记录源码核查、直接近邻以及对现有研究方案的修正；没有启动新的训练或下载模型。

## 已核查的实现

[VGGT 聚合器](https://github.com/facebookresearch/vggt/blob/main/vggt/models/aggregator.py)（读取时 blob SHA `9a69498e2d42a9a635a29acc9b7026f5962c48f5`）默认使用 `dinov2_vitl14_reg`、1024 维、24 层深度和 `aa_order=['frame','global']`。帧内处理对应每帧自己的 token 序列，跨帧处理对应合在一起的多帧序列；输出连接同层两种特征。[模型入口](https://github.com/facebookresearch/vggt/blob/main/vggt/models/vggt.py)（blob `686e6f9d3f9e37769c195258f429a66d927375c0`）再接相机、点图、深度与跟踪头。

因此它的关键是联合推理的表示和监督，而不是单独某一个 attention 运算。DINO 是视觉编码器，不只是机械切图。[原论文](https://arxiv.org/html/2503.11651v1) 使用多种几何目标和广泛训练数据；其中包括 Hypersim、Replica。以后使用其预训练特征，必须披露预训练数据覆盖，不能把我们任务头未见场景称为整个系统完全未见的数据。

## 与我们此前 attention 的实质差别

本地 `memory_resegmentation.py` 中的 `LocalEvidenceReader` 是 384→64 投影、局部查询读取最多 8 个几何邻居，然后预测点对亲和力并生成 SAM 提示。它不联合更新多帧图像 token，没有跨帧共享的可修订对象表示，也没有由最终三维实例目标直接约束地图归属。

之前该实现没有稳定增益，不支持“多帧联合建模没用”的结论。它只检验了那种局部读取、提示与 CG 融合路径。

## 直接近邻改变了创新边界

- [SegVGGT，2026-03](https://arxiv.org/abs/2603.19926)：把对象查询嵌入几何 Transformer，与多层几何特征交互，联合输出几何与实例，并提出帧级注意力分布对齐。因此“VGGT + object queries + mask head”已有直接工作。
- [SAM-V，2026-09](https://arxiv.org/abs/2609.25490)：将 VGGT 的几何特征与 SAM 的分割能力结合，处理跨视角同一实例。[源码](https://github.com/gong208/SAM-V/blob/main/model/sam_vggt_model.py)（blob `b85becb44dc044a953f289f33d57c22801df3bb5`）默认允许冻结 VGGT/SAM 编码器，训练融合与解码模块。[仓库](https://github.com/gong208/SAM-V) 提供推理、训练、评测入口及权重地址；尚未在本机复现。
- [Instance-Structured 3D Tokenization 项目页](https://yoomimi.github.io/instok3d/) 也研究对象结构的三维 token。因此“对象 token”本身也不是待认领的空白。

上述差异依据已读论文/代码的任务与实现，不声称相关领域尚无人研究持久记忆或可见性注意力。

## 建议的机制：有测量依据的对象记忆与历史归属联合更新

保持定位支撑对象语义建图的主线。LIVO 给机器人位姿和实测点；公开数据用其协议规定的位姿与深度。VGGT 的多视图特征可作为表征基础，不自动替换定位、不把预测深度当成 LiDAR 真值。

拟议数据流：

```text
多帧 RGB ── 预训练视觉/多视图表征 ── 局部视觉 token ───┐
                                                   ├─ 联合更新 ── 跨帧实例 mask
实测深度、位姿 ── 可见 / 遮挡 / 未知的几何关系 ─────────┤              源点到对象的软归属
                                                   │              更新的对象记忆
历史对象记忆 + 可检索的源观测 token ──────────────────┘
```

目标不是仅维持旧身份。对象记忆与局部观测双向更新，并重新解码受影响历史源点的归属，使新视角有机会纠正此前合并、碎片和背景污染。历史对象只保留一个均值向量可能再次丢失纠错证据，所以保留多个有来源的局部 token；第一版可检索固定数量，先不宣称最优压缩。

几何关系应作为带不确定性的偏置/有效性标记，不应全部使用硬半径屏蔽。已知遮挡不作负证据、无深度保持未知；位姿与投影误差要通过扰动对照验证。不能以“几何上近”直接监督同实例，避免同类相邻车辆混淆。

训练目标与输出对齐：跨视角共享实例匹配、mask 损失、实测支持上的对象归属损失；只有同一表面对应明确时才施加一致性监督。单纯一致性可能把所有点合成一个实例，必须有区分不同对象的监督和未知/背景处理。类别可先沿用固定读出，隔离实例改进。

潜在贡献集中为一个论点：**受实测可见性约束的对象记忆更新，能在新观测到来时纠正历史归属，并在有界窗口下保持地图质量。** 这是需验证的假设，不把三类 token、注意力或已有损失函数分别包装成创新。

## 先辨别表征收益，再检验新机制

1. 冻结已有强基线和分割预算，先检查 VGGT 联合特征与单帧 DINO 在跨视角同实例辨别上的区别；这只是诊断，不能代替完整地图评价。优先采用公开预训练骨干/分割权重，避免从头重训 VGGT。
2. 统一训练数据与头部容量，比较单帧特征、联合多帧特征、带对象记忆、带对象记忆且可修订旧归属。再用去掉可见性偏置的消融，回答新机制是否有独立收益。具体预算与划分在实施前冻结，不自动追加这些实验。
3. 对全序列报告实例 AP/PQ、碎片与误合并、历史错误的恢复/新增损伤，以及时间、峰值显存、记忆随序列长度的增长。以固定规模窗口起步，不能把短窗口分割结果写成长期建图成功。
4. 保留同条件强方法；SAM-V/SegVGGT 的任务、提示来源、训练集与传感器输入均须对齐或分表。自家模块消融不能替代外部方法对比。

双 RTX 5090 可用于小窗口冻结骨干后的任务头试验；具体可容纳窗口和训练吞吐尚未实测，不承诺全量微调可运行。
