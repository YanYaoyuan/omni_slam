## 预检决定：去掉无法充分区分的选视角主张

16 对中12对只有一个合格取证视角；分歧效用与最大可见面积仅1对选择不同，
随机视角与最大可见面积仅2对不同。继续生成这些地图无法充分检验主动选视角，
因此在新模型调用和评分之前撤掉该项贡献及重复对照。

所有完整地图条件共用已封存的最大共同可见面积动作。原选中候选对不变，
不重新选择能让主动策略获胜的案例。保留原三种视角选择的预检产物供复核。

## 方法要验证什么

对同类观测 A/B 比较保持、分别修订、合并三种对象解释。
对称提示产生两个排斥式掩码（A正/B负，B正/A负）和两个联合正点掩码。
只按原生预测质量选掩码，检查点提示符合度；不使用参考标签挑输出。
提示未被满足的候选不参与提交，原状态始终可保留。

验收只使用原图像列表和此前探针均未使用的 RGB/雷达帧。
新帧只接收类别提示；验证证据来自当前真实雷达回波，缺测保持未知。
两个原争议组在同一验证帧都至少有16个可见物理单元时，该帧才同时用于所有候选。
20 cm单元沿用现有查询记忆网格，不能按 AP 调整。验证单元可见性与旧点的5 cm深度核对不同，见下节。

### 已准备29个新观测，验证接口按真实回波读取物理单元

0000 / 0002分别补取14 / 15帧，四个官方归档合计下载73,031,830字节。
新帧均不在原108帧或能力探针的5帧中，文件哈希核验通过。

最初沿用旧点精确回投到稀疏深度像素的接口时，两个窗口分别只有1/8、5/8组
具备双侧至少16个可见查询单元。该接口没有将新扫描自身的回波作为查询观测，
对新的采样位置覆盖很稀疏；其记录和输出保留在 `verification_inputs.json` / `input_audit.json`。

新增的 `validation_cells_complete.json` 使用当前扫描的真实点，经原相机标定与最近像素
z-buffer选出前表面回波，再用精确姿态和固定原点变换到既有20 cm查询网格。
所有旧单元ID保持不变，新空间单元按帧/像素顺序追加；没有填充深度、膨胀像素或改旧地图。
原来的5 cm回投接口保持不变。新表示是“当前实际观测到该单元”，
不是“该单元里的每一个历史点都通过了5 cm深度核对”，不能混用两种解释。

在相同候选和相同帧号上，新表示使两窗口均为8/8组至少有一个可验证视角，
分别3/8、4/8组有两个视角。这只证明验证观测覆盖，不能当作准确率提升。
20 cm单元的边界混叠仍是限制。所有完整地图条件共用新表示；新扫描点只用于验收，
禁止追加到评分地图，避免把额外采样点数混入方法收益。

决策核心在统一可见域上比较候选对象与查询掩码的加权 IoU。
一个对象匹配一个查询；两个对象匹配两个不同查询，并按查询掩码的重叠程度折扣，
避免把两个几乎相同的查询编号当作两个实例。
原生分数仅为权重，不称为校准后的身份概率；重复查询不累计票数。
各合格验证帧等权平均，严格优于保持原状才提交；无合格帧或数值并列均保持。

保持/分别修订要保留未被当前测量否定的历史来源。
分别修订只改写本次争议范围内、具有当前测量支持且落在唯一新掩码中的历史点归属；
双掩码或无掩码的点保留原分配。合并在验收后统一相应历史 ID。
不移动旧点坐标，不改写无关对象，不用补全深度产生新点。
新增点必须来自真实测量且全局唯一；待确认对象的出生与语义置信度必须对所有条件使用同一规则，
不能把新质量评分或排序收益混入关联贡献。最终导出细节随实现一起冻结。

`propose_measured_sources` 已实现局部实测源点提案：保留未见历史、按排他新掩码更新归属，
新增且同时落入两个分离掩码的点不强行分配；已由底图保护的源点不重复追加。
跨不同争议对的全局独占分配、真实地图投影和对象记录导出已在`run_partition_revision.py`完成，
并在最终协议中固定。自验证消融仍共享新视角的出生资格核对，只消融划分验收视角。

## 六个完整地图条件，每窗口六份，共十二份

| 条件 | 用途 |
|---|---|
| 冻结几何关联底图 | 当前更强的完整地图控制；逐字节复制 |
| 普通正点重分割 + 新视角验收 + 历史修订 | 同一候选/视角/四次解码预算，检验对称提示是否超越普通重分割 |
| 对称提示 + 提示帧验收 + 历史修订 | 明确的自验证消融，检验分离验收；不允许混入 Ours |
| 对称提示 + 新视角验收 + 只更新当前观测 | 检验修订历史归属与聚合历史几何的必要性 |
| 仅既有候选划分 + 新视角验收 | 检验新增掩码是否必要；它成本更低，不能标为等预算推理 |
| **Ours：对称提示 + 新视角验收 + 历史修订** | 完整候选机制 |

普通重分割的四次解码为 A1、B1、A2、B2 各自正点提示，
与对称方法使用同样的种子像素、分辨率和原生掩码选择。
前两次形成分离候选，后两次掩码并集形成联合候选，均由相同验收器比较。
所有条件共享冻结候选、语义类别、测量输入、源点独占及最终导出约定。
同时保留此前不变几何强基线的已有分数；不把更弱的失败关联图当作唯一基线。

自验证消融必须在代码中显式区分，不能绕过 Ours 的提示/验收分离检查后仍称其独立验证。
读取和历史修订消融可复用模型缓存，报告逻辑调用预算和实际编码/解码成本；
不能为了“等预算”重复计算没有信息作用的调用。

## 实验与交付边界

先封存所有实现、模型、候选、输入和导出规则，再执行上述条件；
全部十二份完整地图封存后统一评分，不按中间 AP 调整。
报告完整窗口 AP50:90、AP50、车辆/建筑分项、正确实例新增/丢失、实际历史改写和耗时。
局部验收分数、点数或提示符合度均不能代替这些结果。

沿用原对象假设研究设计的继续条件：两个开发窗口均超过本轮最强等预算控制，
均有净新增正确实例，完整方法相对只更新当前观测有可归因收益。
冻结几何底图也必须纳入比较。所有版本同分、没有有效修订，或收益仅来自普通重分割时，
停止该机制版本，不改名或扩大数据后继续追分。
这不是降低此前各失败版本的门槛，它们的冻结判定保持不变。

已有三例能力探针的决策核重放分别输出 split、keep、merge。
其中“merge”只是算法选择，未读取GT确认；该检查没有改地图或产生 AP，
也不是在保留历史来源后的最终候选几何评分。

开发通过后再冻结同一版本进行机器人对照及真正未参与开发的公开场景评测。
