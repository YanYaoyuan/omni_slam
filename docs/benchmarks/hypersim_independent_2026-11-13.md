## 数据与输入

- 官方 test：`ai_001_010`、`ai_003_007`，各 `cam_00` 全部 100 个公开帧。依据官方元数据按场景名排序选择，选择发生在查看这些场景的预测或分数之前。
- 官方 train：`ai_001_001` 的 5 帧只用于接口适配。
- 数据来源：[Hypersim 官方项目](https://github.com/apple-aiml-research/ml-hypersim)。原始数据以 HTTP Range 按文件提取，检查 ZIP CRC 和 SHA-256。没有下载整套 1.9 TB 数据。
- 所有方法使用同一套原始 HDR 图像，按官方 90% 亮度分位归一化及 gamma 转换，保存无损 PNG。没有将 JPEG 预览作为正式模型输入。
- 按官方逐场景投影矩阵将径向距离转换成轴向深度，米制位姿转换成 CV 相机约定。两场景全部帧的针孔/射线转换最大误差小于 5e-15 m；毫米深度量化误差不超过 0.5 mm，没有超过 uint16 深度范围的有效像素。
- 训练样本另与发布的逐像素世界坐标比较，全部误差在原始 float16 存储的量化上界内。预测阶段不读取语义或实例标注内容。

## 比较方法

1. CG，共享前端适配。
2. 原强基线 History2。
3. History2 + SOR。
4. History2 + visibility1：旧稿中的冻结 Ours。
5. History2 + simple ratio：当前必须比较的强对照。
6. History2 + MaskClustering 风格点比例过滤。
7. 漏分模型：统一召回率。
8. 漏分模型：逐视角召回率。
9. 漏分模型：逐视角召回率，排除被评估点对自身统计量的贡献。
10. MaskClustering，共享前端的官方核心及后处理适配。

所有方法共用冻结 SAM2.1 / SigLIP / 描述子融合与几何缓存。两个外部核心适配不等同于各自原版完整检测器流程。方法 3–9 作用于同一个 History2 地图，分别应用一次后处理，不叠加 SOR。固定身份过滤不改变类别或创造新源点。

## 评分与隔离

主指标为可观测表面上的类别无关实例 PQ、SQ、RQ，严格 IoU > 0.5。原有分配点最近邻转移，距离上限 5 cm；所有非空 GT 实例纳入主指标。另报告排除不足 20 个参考体素的 GT 实例后的敏感性指标，不择优选指标。

参考域由两场景各自 100 帧的真实深度和实例标注产生，固定每 4 像素采样、5 cm 体素；参考位置为体素内样本质心，标签为含背景在内的多数票，平票取较低 ID。未标注像素不参与。NYU40 的 wall/floor/ceiling 作为背景，其余有效实例保留；原始实例 ID 0 平移为有效正 ID，不能误当背景。

两场景的所有预测先完整封存和哈希，再读取实例标签、生成共同参考和评分。该指标不是官方 Hypersim 挑战分数，也不评价未观测完整网格；与原 SceneNN 的绝对数值不直接混为一个数据集均值。

实际评测代码已用合成文件验证：未封存时阻止 GT 读取；实例 ID 0、背景、未知区域和重复帧体素化正确；完美预测 PQ=100，两个等大实例误合并后 PQ=0，确认 IoU=0.5 不被错误计为匹配。

## 用户补充的室外研究方向

用户提供 [Urbex](https://arxiv.org/abs/2610.18356)，要求检查其思路和 benchmark。已阅读方法图、主结果与数据附录，并核对官方代码和数据说明。Hypersim 冻结评测现已完成；室外数据接口与有界下载已启动，尚未启动室外训练或语义评测。已有室内配置与成绩不变。

- [KITTI-360](https://www.cvlibs.net/datasets/kitti-360/documentation.php)：作为室外顺序建图的优先数据，提供图像、原始雷达、标定、位姿和跨帧一致实例 ID。先固定给定位姿与前端以验证对象地图模块；静态实例和动态对象应分别定义评测范围。已通过官方公开归档链接取得样本，无需用户重新下载。
- [CityRefer](https://github.com/ATR-DBI/CityRefer)：用于已有城市地图的语言定位。须区分原始数据划分与 Urbex 的清洗后 ND / NO 划分，GT 候选上限与预测地图也应分别评分；Hit@1 不能代替实例几何指标。
- [Urbex 数据](https://huggingface.co/datasets/vvangfaye/Urbex-Data)：提供处理后的标注、BEV 和斜视缓存，STPLS3D 原始 PLY 可选下载；SensatUrban 原始点云需要另从官方获取。STPLS3D-Refer 是作者构建的真实场景语言定位集合，不能称为 STPLS3D 原生实例分割 benchmark。
- [STPLS3D 官方说明](https://github.com/meidachen/STPLS3D)：原生实例标签只在 synthetic v2/v3 中提供；真实点云、合成实例任务和 Urbex 派生 Refer 集必须分清。官方另提供源图像入口，不能笼统说该数据集没有图像。

可研究的假设是：按需选择有区分力的真实历史视角，对有歧义的对象局部重新取证，并将经验证的修订保存在持久地图中。先在固定视角预算下比较随机取帧、最近关键帧、按可见面积选帧与证据选择；同时测完整地图质量、查询成功率和计算量。该假设尚未实现或验证，不将加入 agent 本身写成贡献。从同一地图渲染的多视图也不能冒充独立传感器证据。

### 论文借鉴与实验边界

Urbex 的输入是已有城市三维场景与文字查询，输出目标空间框。核心流程是全局 BEV、地标查询、局部放大、斜视检查及提交框；用 GRPO 训练 Qwen3-VL-4B 的工具选择策略。它验证的是空间搜索，未提供从机器人传感器流逐帧建图的对照。因此，它适合作为下游任务与预算分配机制的参考，不直接替代我们的建图强基线。

论文附录 B 的 CityRefer 经过清洗并重新划分：12 场景，2,744 train、549 validation、1,098 ND、1,396 NO 查询；NO 为 7 个未参与训练的场景。STPLS3D-Refer 是作者从两个真实航拍场景构建的零样本评测，包含 149 个建筑/车辆候选实例、445 条描述。其对象与描述经过半自动生成和人工筛选，不能称为原生 STPLS3D 官方实例评测。

论文表 1 中 CityRefer-NO 的 Hit@1 为 23.9，对照 CityAnchor 为 14.2；另五次解码均值为 23.53。该指标按预测 BEV 框与候选框的 IoU 排序，不要求最小重叠；增加目标 IoU≥0.25 的条件后，五次均值为 18.71。无 GT 候选设置还报告 3D IoU、Point F1。我们若使用这个下游任务，应保留几何重叠指标，不能只用 Hit@1 证明地图准确。

我们最值得检验的差异是：用真实历史观测补充对象证据，并把修订保存在地图中，让多个后续查询复用。Urbex 式渲染可辅助选位置，但同一错误地图的另一幅渲染不是新的测量。这个差异目前是研究假设；必须通过“局部高分辨率处理本身”与“视角选择策略”的独立对照才能支持贡献。

受控验证顺序：

1. 先完成 KITTI-360 输入、类别映射、参考域与评测器适配；建筑不能沿用室内 background 排除规则。静态参考只支持静态实例范围，不能把运动车辆混为静态建图成绩。
2. 同输入对比冻结 History2、SOR、简单比例、MC-style 过滤、Ours visibility1，识别实际室外错误。所有方法用相同给定位姿、前端、输入帧与参考域。
3. 只有开发窗口中存在可由已有真实视角修正的具体错误，才开展一次固定预算的视角取证假设验证：相同局部重分割模块，分别随机/最近/可见面积/证据选择。分别记录目标选择、分割变化和完整地图得失，避免把调用次数增加归为策略收益。
4. CityRefer 作为后续应用验证，比较相同查询器作用于原地图与修订地图，并区分 GT 候选、预测候选和无候选设置。只有一次查询的搜索成功不支持持久地图改进，需测试修订后其他查询和被修订对象之外的退步。

当前只进入第 1 步。两个预留验证窗口不用于选阈值；若后续查看了标签或得分并用于开发，须如实修改其状态。三窗口只是适配与首轮验证，不能代替完整官方榜单或充分的室外泛化评测。

评价使用哈希固定的官方匹配/AP函数，并显式适配两个上游兼容问题：旧NumPy标量别名，以及官方`annotation.py`构造函数只接受2个参数、评测调用却传3个参数的不一致。兼容类按评测器的置信度加权定义计算区域面积。因此准确名称是**基于官方核心的本地适配评测**，不称官方服务器成绩。AP阈值仍遵循下载代码的0.50至0.90加0.25，主报AP50。20cm最近点转移包含全部对象，非目标对象以零标签参与近邻竞争；可观测诊断按共同原始测量支撑限制参考域，不按预测结果挑区域。

权威图文报告：`output/kitti360_connected_development/index.html`、`report.md`。其中有真实RGB/掩码、参考与预测地图、逐对象支撑诊断。`evaluation/verification.json`已核验1,146,133个支撑点的原测量归属、过滤输出的精确源点子集、类别不变及16项域/方法AP算术。

下一模块的证据边界：建筑前端覆盖与目标分类不足，车辆还存在漏分及融合损失；不能期待只删除已有对象点就恢复这些目标。源码核查还发现`multi_crop: true`未传入SAM2的`crop_n_layers`，当前配置不能声称实际启用了多尺度裁剪。后续若验证主动局部取证，必须包含真正的普通多尺度裁剪强对照，固定额外调用预算，分别验证分割恢复、类别恢复和完整地图收益。两个预留验证窗口继续保留，不提前运行或调参。

我们当前完整强基线与Ours都只有**单个已暴露开发窗口的本地AP50=8.7692%**，其中building=0、car=17.5384%。与榜单不同之处包括：开发窗口与官方测试集不同；我们的输入是60个采样时刻的前视RGB/稀疏LiDAR及给定位姿，输出经20cm近邻转移到参考点；榜单为完整任务的测试集平均，方法详情没有提供足以证明相同传感器/输入预算的信息；本地评测还有已公开的兼容适配。故不计算“落后官方多少点”或声称官方排名。可观测诊断11.6667%更不能替代完整域AP50参与榜单比较。

我们还不能把本地完整AP=4.0594%直接放到官方AP列：官方网页指定0.50..0.95十个门限，下载代码只计算0.50..0.90九个门限（另报AP25）。AP50没有这一门限集合差异，但仍需一致数据划分、参考域与输入协议。

另一个 [Semantic SLAM建图榜单](https://www.cvlibs.net/datasets/kitti-360/leaderboard_semantic_slam.php?task=mapping) 使用几何Accuracy/Completeness/F1与语义mIoU，不是对象实例AP。S-DSP页面成绩为F1=75.64、mIoU=37.59；其详情说明使用ORB-SLAM2位姿、SGM深度、CMNext二维分割，不能与我们的8.77 AP50直接数值比较。

正式对比路径：先在公开验证划分、共同窗口和清楚声明的输入条件下运行外部实例方法，保留完整点云与传感器建图两种任务条件的区别；提供全部目标类别、逐类AP50、统一后处理和预算。完整官方测试评测是后续单独交付；目前没有上传预测或产生官方成绩。若强基线的building仍为0，优先修复前端/分类和覆盖问题，不能只在已知车辆上增加若干点过滤对照后声称达到官方强方法水平。
