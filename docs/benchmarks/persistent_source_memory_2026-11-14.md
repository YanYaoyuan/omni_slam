# 持续对象记忆：训练与完整地图对照

2026-11-14。本轮已完成四次训练、八份完整室外地图及评分。**候选失败，保留原强基线；不扩展本版到机器人或独立测试。**

[图文报告](../../output/persistent_source_memory_v1/index.html)包含实际 KITTI-360 图像、完整地图、全部训练曲线及 94 个合格 GT 对象的 IoU。

## 主线与本轮交付

主线仍为 omni_slam 持续对象级语义建图，LIVO 提供机器人定位与实测几何。本轮落实原 `JointObjectMemory` 尚未执行的训练环节，不再把未训练注意力的诊断当作训练结论。

- 实现 `PersistentSourceMemory`：继承帧内/跨帧注意力、持久对象槽位，增加可分块的全源点读出。
- 实现因果观测账本：每个实测点保留最后观测的图像位置、帧号和在线类别证据；从未出现的源点不能读取。
- 108 次冻结 VGGT 推理，每次仅当前及此前最多三帧，只保留当前图像的 patch 特征。没有使用预测深度造点。
- 两窗口共 2,064,298 个原始实测源点全部进入最终读出范围。训练查询采用固定抽样，并非对全部源点逐个监督。
- 11 项核心测试通过；全部帧的因果指针、在线概率以及 109,556 条查询外观经独立重放验证。
- 四次任务头训练：0000→0002 和 0002→0000 各训练有/无几何关系两组。每组固定 40 轮，合计 2,160 次优化更新，无早停、选权重或参数搜索。

这不是 VGGT 全量微调，也不是新的定位算法。两个窗口早已暴露，是开发对照；既有强基线继承此前开发过程，不能把结果称为严格嵌套交叉验证或官方榜单。

## 机制和必要对照

模型有 128 个固定槽位，源点可分配到对象或背景。槽位跨帧传递，不在推理时使用 GT 匹配，不静默回收。上下文最多 512 个 token，但完整源点账本仍随数据增长，不能宣称总内存有界。

当前及历史 token 中，精确同一实测源点提供正关系；不同源点投影到同一已测像素但深度冲突提供软关系。后者不是“不同对象”标签。缺测保持未知。

| 条件 | 权重与状态 | 最终源点归属 |
|---|---|---|
| 原强基线 | 冻结 geometry_graph | 原样复制 |
| 当前提交 | 完整几何模型 | 每个点最后可见时的预测 |
| 无几何 | 同容量、同数据独立训练 | 用末尾记忆重新解码所有点 |
| Ours 候选：历史修订 | 与当前提交完全相同 | 用末尾记忆重新解码所有点 |

当前提交对照执行相同的最后一次解码但丢弃结果，避免把推理预算差异混入比较。此消融隔离窗口结束时的历史归属重解码；不是“无任何记忆”的独立训练对照，也不是每帧全量重写历史。

分类统一使用所属源点在线 19 类概率的均值，保留 car/building；对象置信度结合槽位存在概率。全部学习条件没有 SOR、连通域、人工修图或强基线回填。新增输出均为原实测坐标。

## 训练前的输入修正

初始均匀抽样上下文只产生 38 / 29 对非零几何关系，其中精确重复源点分别为 0 / 1 对，难以检验几何机制。**在生成训练标签、优化或评分之前**，改成每帧优先取回最多 128 对当前再次看到的实测源点，再补其他历史和当前样本；上下文预算不变。

旧协议、代码和输入包保留在 `pretraining_preflight/` 与原 `prepared/`。新包位于 `prepared_retrieved/`，修正见 [记录](../../build/benchmarks/persistent_source_memory_v1/pretraining_revision.json)。未增加基础模型调用、训练次数或地图数量。新上下文实际包含 7,552 / 6,016 对重复源点和 140 / 72 对测量射线冲突。这是输入覆盖检查，不是准确率。

最终训练和评分以 [protocol.json](../../build/benchmarks/persistent_source_memory_v1/protocol.json) 的修订协议为准；`freeze()` 的初始文本与归档记录属于修正前的历史阶段。

## 为什么失败：对象槽位失去区分

四个冻结模型的实测输入重放显示，全部槽位两两余弦相似度超过 0.999 的首次位置为第 2–12 个采样帧。末尾最小余弦相似度约 0.9999996–0.9999998，前景实例 logit 的平均极差仅约 `6e-7` 至 `8e-6`。状态矩阵首奇异值几乎解释全部能量。

这支持“当前循环更新实现发生槽位坍缩”的判断，而非模型完全未训练。损失确实下降，但没有学成稳定的实例区分。推理代码让所有槽位读取相同的全场景上下文，包括尚未形成对象或当前未看到的槽位；随机初始化槽位被同时要求学会对象形成和历史修订，不能稳定承担这两个任务。

连续输出的分块一致性测试通过。实际最后一帧同输入、同状态的离散 ID 复算也保持一致，改变点数均为零。因此**不能声称已观察到这一复算中的数值批次翻转**。近相同 logit 暴露了数值风险和实例区分不足；真实历史变化本身仍不等于正确纠错。

[逐帧状态诊断](../../build/benchmarks/persistent_source_memory_v1/state_diagnosis.json)没有新的训练、地图或 GT 读取。它不证明所有注意力、学习方法或对象记忆都无效，也不自动支持延长训练。

## 去留决定及后续约束

1. 封存这个随机槽位、全场景读取版本，不搜索轮数、阈值、随机种子或改解码补分。
2. 保留原强基线。下一实现应以已有对象及其带来源观测作为身份起点，不再让新头从零替代成熟的对象形成前端。
3. 只在有该对象的实测观测证据时更新其记忆，未见对象保留；修订仍针对历史源点归属。是否训练、是否用注意力都不是预设结论。
4. 同输入对照必须包含简单的对象原型平均/检索更新，避免把“修复坍缩”本身包装为创新。最终仍比较完整地图、逐对象恢复与损伤。
5. 保持对象身份只是下一机制的必要条件，不是已实现优势。只有开发验收通过后才冻结同一版本，执行真正未使用场景和机器人对照。

完整目标尚未完成：本轮有训练后的新机制实现和完整开发对照，但没有有效新方法、该版本机器人验证或新增独立测试。旧机器人链路不冒充本版验证，0000/0002/0003/0004/0005 不再称未见测试。
