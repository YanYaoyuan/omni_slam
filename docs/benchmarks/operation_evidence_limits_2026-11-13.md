# 主线决策：不要继续在已丢失对象的输入上训练末端修订

[真实掩码、完整源点支持诊断与评测覆盖报告](../../output/operation_evidence_audit_v1/index.html)。

本轮只读取已封存预测和缓存，不训练、不调阈值、不生成新地图。此前对象操作收益模型已经封存。这里的证据用于决定下一机制作用在哪个阶段，不是另一轮开发涨点。

## 室外存在明确的输入能力限制

当前 KITTI-360 drive_0000 开发窗口有 31 辆可评估车辆、18 个建筑。以下计数表示该阶段测量支持在 20 cm 范围内覆盖了超过一半的置信度加权 GT 面积，允许完美点级归属与背景剔除，因此是**必要条件诊断，不是 AP 或可达到的召回**。

| 支持域 | 测量点 | 车辆覆盖 > 1/2 | 建筑覆盖 > 1/2 |
|---|---:|---:|---:|
| 全部测量 | 1,146,133 | 29 / 31 | 9 / 18 |
| 原掩码支持 | 236,547 | 26 / 31 | 0 / 18 |
| 最大连通分量支持 | 155,666 | 23 / 31 | 0 / 18 |
| 至少三帧历史组 | 78,455 | 16 / 31 | 0 / 18 |
| 最终对象观测 | 78,455 | 16 / 31 | 0 / 18 |
| 强读出后的目标前景 | 34,790 | 16 / 31 | 0 / 18 |

源点支持域逐项验证嵌套。以实际评分的背景阻挡竞争再检查当前固定前景，也得到车辆 16、建筑 0 的必要覆盖计数。这不意味着其中 16 辆车都能匹配成功。

结论有明确先后顺序：

1. 建筑在原掩码支持阶段已经不足，不能用末端对象合并/重分配恢复。
2. 车辆在掩码到连通支持阶段损失 3 个充分覆盖目标，在三帧历史组阶段又损失 7 个。历史组损失可能包含分碎关联与帧数过滤共同影响，不能只凭此表断言降低帧阈值就能恢复正确实例。
3. 当前强类别读出下，语义前景筛选没有进一步降低这项车辆覆盖计数；不能重复把当前所有问题归因于早先已处理的类别读出。
4. 当前修订输入只含 81/340 个缓存观测，任何仅在该集合中改变归属的方法均不能补回被排除的观测。

## 室内错误合并的证据

SceneNN 014 的对象 55、66 各有四个保留观测，所有原始 RGB 与八个掩码已放入报告。它们是相邻的不同枕头区域，模型却因语义外观相似而将二者合并。

16 个可能的跨对象观测对只有两个候选边；两条边的测量支持交集均为零，SigLIP 余弦为 0.874、0.864，同对象概率却为 0.863、0.785。候选模型使用的是原 SigLIP 描述子，不是新增的密集 DINO/VGGT 局部对应证据。

两组保留观测的帧号无交集，所以只给这些观测加同帧互斥没有作用。完整缓存中虽然有 8 帧同时触及两组源点，但部分支持来自同一大掩码或其他对象掩码，覆盖偏低；不能把这项事后发现直接升级成可靠禁止合并规则。

## 零操作的原因已定位

KITTI-360 的 9 个候选操作预测收益全部为负，风险概率仅约 0.00025–0.00040；车库 23 个候选也全部为负，风险概率约 0.00017–0.00908。不是风险阈值 0.1 导致零操作，放宽风险阈值不会改变结果。

## 下一机制的范围与必要对照

不再围绕本版提交筛选器搜索参数。下一机制必须让地图能够利用**当前保留集合之外的对象证据**，具体区分两种问题：

- 无足够掩码支持的区域：要能生成新观测；仅替换描述子或重排旧身份无效。
- 有测量与掩码、但因历史组不足而被排除的对象：应保留候选对象记忆，按可见观测机会核验其存在与身份；要与简单降低最小帧数的强对照区分。

后续若采用 SAM3，它只是生成候选掩码的工具，必须设置相同 SAM3 前端的普通建图对照，不能把换模型收益直接写成记忆机制贡献。本地 `/home/user/vbot/sam3` 源码及 `checkpoints/sam3.pt`、`model.safetensors` 均存在（各约 3.3 GB）；本轮未运行新推理，未声称环境或 GPU 就绪。

是否值得实现统一新机制，还需要核对相关方法与设计一次有限预算验证。不能因为找到输入缺口就自动堆叠模块。

## 新增评测的实际准备度

本地官方划分文件包含 239 个训练窗口、61 个验证窗口。当前实际下载了 3 个选定窗口、161 个采样帧，其中验证窗口只有 2 个，均已暴露。不是完整大场景或完整官方划分。

新的独立评测需先按元数据选择未暴露窗口，下载图像、实测 LiDAR、位姿和未解码参考，核查轨迹与实际支持的空间重叠。候选通过开发验收后，再冻结配置、封存全部预测并评分。当前没有新增独立成绩。
