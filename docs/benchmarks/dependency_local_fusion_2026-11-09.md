# omni_slam：依赖局部重算与全量重放对照

2026-11-09。完成八场景、三种修正范围、两种扰动幅度、三种策略，共 144 个独立进程实验和 432 次位姿修正；另完成两段真实录包的 18 次修正及 office_0 的 60 次重复计时。

**局部场景中，相对带缓存全量重放的速度比几何均值为 1.75×，28/32 组更快；所有主实验的对象身份及几何与全量参考一致。** 广域修正的速度比几何均值为 0.74×，低于 1 表示更慢。预先锁定的成本判据：通过。这支持有条件的局部更新收益，不支持无条件替换全量重放。

## 本轮实现

新增依赖节点缓存：观测 ID 与精确位姿版本确定输入节点；有序输入状态确定融合/去噪节点；相同输入复用结果，变化沿计算依赖重新求值。每次仍遍历全部帧，以保留帧内决策顺序及去噪时钟；局部性体现在评分、点云融合及去噪的重算量。更新成功后才发布，历史因果输出不变，旧版本缓存按当前依赖图裁剪。

最初的空间包围闭包在两个开发场景均扩大至全图（625/625、1510/1510 观测），因此保留为失败对照。最终候选采用精确输入依赖，不用事后挑选的空间半径截断影响范围。详细机制和数值分支见[方法说明](../paper/dependency_local_fusion_method_2026-11-09.md)。

## 冻结协议与对照

八个 Replica 场景均已在前期查看，每场景固定 200 帧，不能称为新独立测试。固定改变前 10%、后 10% 或全部关键帧；扰动从零附近线性增长到 0.05 m / 0.75°（small）或 0.2 m / 3°（large），再恢复数据集提供位姿。平移数值指世界变换分量，绕世界原点旋转也会改变相机位置；局部区间边界可以有不连续，属于明确的受控更新，未模拟真实 SLAM 误差分布。

三种策略：原生全量重放；复用观测预处理及已有最终快照的带缓存全量重放；额外复用评分、融合和去噪节点的依赖局部重算。第二项用来隔离普通缓存的收益。前端沿用冻结预测观测与 CLIP；关联、融合及最终处理保留官方 ConceptGraphs 核心，非原版完整前端复现。官方版本、权重及独立环境见[前期固定配置](expanded_semantic_2026-11-09.md)。

每个场景/条件/策略在独立进程执行，在 AMD Ryzen 9 9950X 上固定单个逻辑 CPU，四个主工作进程使用 CPU 0/2/4/6。每次更新都从相同原状态出发，更新中产生的新缓存不会成为下次重复的热缓存。方法顺序按固定随机种子打乱。耗时包括完整更新与最终标签获取，不包含检测和特征提取；内存为更新期间每 5 ms 采样的进程 RSS，包含共享库、原始证据、保留旧状态和候选新状态，不是 GPU 内存。

预注册判据：32 组局部组合的速度比几何均值至少 1.5，且至少 75% 比带缓存全量更快。三次重复用于描述波动，不作为统计显著性检验。所有慢例、广域结果和初始化成本都保留。

## 结论与论文边界

本轮将“能否保持全量质量并降低局部更新成本”落实成代码、固定协议、完整正反例及可重复计时。当前证据的范围是已有八场景、固定前端和原生融合配置下的受控位姿更新；没有新数据泛化、端到端语义精度提升、板载实时性或在线回环恢复延迟结论。依赖重算与缓存是已知计算思想，还需与最接近的增量建图实现比较，才能判断论文新颖性与贡献。

下一阶段应研究受影响依赖的代价预测和可靠的全量/局部调度，并在包含新观测到达的长期在线流上验证缓存生命周期。对新场景、标准实例指标和更大地图的验证仍然必要，不能由本轮开发结果代替。
